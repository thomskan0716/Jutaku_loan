- 12種類の画像

- 2026年10月 サービスイン

## F分類レベル&E分類レベル

### F分類レベル - 処理手順
ステータス: MIGRATION_BATCH_Cから100%再利用可能

F分類レベル = どのように処理するか(軌道・手続きの順番)

1. processAll()
   マスタデータをロード → HashMapキャッシュ

2. claimNextRange()
   FOR UPDATE SKIP LOCKED → 並列実行

3. processOneRange()
   データ変換 → E分類レベル適用

4. markDone() / markError()
   ステータス更新 → 継続/再試行

主要パターン:
  - レンジベース処理
  - HashMapキャッシュ(N+1クエリ防止)
  - 並列実行制御(15バッチ)
  - トランザクション境界
  - エラーハンドリング&ロールバック

### E分類レベル - コードマッピング
ステータス: 65-70%完了(段階的に追加)

E分類レベル = どのコードを変換するか(コード変換)

例: E申込目的(申込目的)

旧システム → 新システム
10 (新規新築) → 10 (新規借入)
15 (新規中古) → 10 (新規借入) ← 統合
20 (借換) → 20 (借換)
30 (借換諸費用込) → 20 (借換) ← 統合

50以上のEnumカテゴリ:
  - E申込目的, E審査種別, E審査ステータス
  - E担保種別, E建物構造, E住宅種別
  - E返済方法, E金利区分, E借入目的
  - E勤務先形態, E年収区分, E承認区分
  - ...その他40以上

## 変換パターン

| パターン | 複雑度 | 例 |
|---------|-----------|---------|
| 1. 直接マッピング | 低 | 申込番号 → 申込番号 (1:1コピー) |
| 2. コード変換 | 低 | E申込目的.fromCode() → 新コード |
| 3. N:1集約 | 中 | 複数の担保情報 → 単一の申込担保情報 |
| 4. 縦 → 横変換 | 高 | 収入情報(行) → 年収情報(列) |
| 5. 横 → 縦変換 | 高 | 返済計画(列) → 返済予定(行) |
| 6. PK変換 | 中 | "HL"プレフィックス追加 + パディング |

## 移行基準

### 移行対象(これらを移行)
- 事前審査完了
- 正式審査完了
- 承認および否決・取り下げの両方のケース

### 移行対象外(移行しない)
- 審査中
- 未紐付け画像
- カットオーバー後に顧客が再申込
